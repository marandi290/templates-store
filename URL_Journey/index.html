The URL Journey

What happens between typing a URL and seeing a webpage — step by step.

🌐

Step 1

Browser

You type a URL. The browser needs to resolve it to an IP address.

⚡

Step 2

Browser Cache

Checks local DNS cache for a stored IP address.

Fastest path
🔍

Step 3

DNS Resolver

ISP's recursive resolver queries the DNS hierarchy on your behalf.

🌍

Step 4

Root Server

Directs the resolver to the correct TLD name server (e.g. .com).

🗂️

Step 5

TLD Server

Points to the authoritative name server for the specific domain.

📋

Step 6

Auth. Server

Returns the final IP address for the domain to the resolver.

🖥️

Step 7

Web Server

Browser connects via TCP/IP and the server returns the HTML page.

Steps 3 – 6 are only reached when the IP is not found in the browser cache or OS cache.

⚡ Why the Browser Cache is the Fastest Step

When your browser successfully resolves a domain, it stores the resulting IP address locally in its DNS cache for a period defined by the record's TTL (Time To Live). On your next visit, the browser checks this cache first — before contacting any external server.

Because the cache lives directly in memory on your device, there is zero network latency — no packets leave your machine. This makes it orders of magnitude faster than any other step in the journey, which each require at least one round-trip across the internet. Effective caching is one of the most impactful performance optimizations available to both browsers and web developers.
